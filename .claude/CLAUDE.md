## 開発スタイル / 好み

- 会話は全て日本語にしてください
- モデルの使い分け
  - **Opus**: 思考、設計、プラン作成、複雑な判断を伴うタスク
  - **Sonnet**: 実装タスク、定型的な作業パターン、決まったコード生成

## やってほしくないこと

- 下記ファイルへのアクセス、および内容を閲覧する行為（log 出力・ファイル読み込み・コマンド経由など、手段を問わず）は禁止です
  - `.env`
  - `.env.*` （`.env.local`, `.env.production` など全て対象）
  - `.envrc`
- 依頼されたタスクの範囲を超えた作業を勝手に実行することは禁止です
  - 例: コードの最適化、テストの追加・修正、リファクタリング、コメントの追加、未使用コードの削除、依存パッケージの更新
  - これらはユーザーが明示的に依頼した場合のみ実行してください。「ついで」に行うのは禁止です
  - 判断に迷う場合は実行前に確認してください

## コマンド実行の作法

承認プロンプトを増やさないための規約です。`permissions.blockReadsOutsideWorkingDirectories`
が有効なため、シェルパーサが静的に解析できないコマンドは「作業ディレクトリ外を読まないと
証明できない」として毎回確認になります。

- ファイルの閲覧・検索は、組み込みの read-only コマンドを明示パスで使う
  - `cat` / `head` / `tail` / `grep` / `find` / `ls` / `wc` / `diff` / `stat` / `du` / `which` / `echo` / `pwd` と読み取り専用の `git`
  - これらは承認プロンプト無しで通ります
  - プロンプトが出ないのは「安全だから」ではなく「静的に検証できるから」です。
    作業に不要なディレクトリを覗いてよいという意味ではありません
- インライン実行でファイルを読んだり加工したりしない
  - 使わない: `python3 -c` / `python -c` / `node -e` / `perl -e` / `ruby -e` / `bash -c` / `sh -c`
  - スクリプトファイルに退避して `python3 <path>` / `bash <path>` の形で実行するのも、
    hook がコマンド文字列しか見られない以上ガードレールを迂回する経路になります。
    その場しのぎのスクリプトを書いて実行することで確認作業を通そうとしてはいけません
  - 定型処理のためにスクリプトが必要な場合は、目的と処理内容を user に伝えて判断を仰ぐ
- 裸の `cd` を使わない
  - `git -C <path>` / `pnpm --dir` / `make -C` / `npm --prefix` などのディレクトリ指定オプション
  - またはパス引数を絶対パスにする
  - どうしても必要な場合だけ `( cd A && cmd )` とサブシェルに閉じる
