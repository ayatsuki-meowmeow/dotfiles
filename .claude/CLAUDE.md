- モデルの使い分け

  - **Sonnet**: 実装タスク、定型的な作業パターン、決まったコード生成

## やってほしくないこと

- 下記ファイルへのアクセス、および内容を閲覧する行為（log 出力・ファイル読み込み・コマンド経由など、手段を問わず）は禁止です
  - `.env`
  - `.env.*` （`.env.local`, `.env.production` など全て対象）
  - `.envrc`
- 依頼されたタスクの範囲を超えた作業を勝手に実行することは禁止です
  - 例: コードの最適化、テストの追加・修正、リファクタリング、コメントの追加、未使用コードの削除、依存パッケージの更新
  - これらはユーザーが明示的に依頼した場合のみ実行してください。「ついで」に行うのは禁止です
  - 判断に迷う場合は実行前に確認してください

## コマンド実行の作法

- `awk` / `sed` / `cut` / `tr` / `xargs` / `jq` / `yq` は使わない
  - これらは「テキストを読む道具」に見えて、実体はファイル書き込みや外部コマンド実行が
    できる処理系です（`awk` は `print > "file"` / `system()`、`sed` は `-i` / `w`）。
    サンドボックスの書き込み許可は作業ディレクトリを含むため、ここは OS では止まりません
  - ファイルの閲覧・検索は `cat` / `head` / `tail` / `grep` / `find` / `ls` / `wc` /
    `diff` / `stat` / `du` / `which` / `echo` / `pwd` と読み取り専用の `git` を明示パスで使う
  - これらで表現しきれない加工（セクション単位の抽出、集計、JSON 手術など）に
    手が伸びたら、そこで止めて目的を user に伝える。処理系を持ち出して回避しない
  - 多くの場合、`grep -n` で見出し・目印・検索語をまとめて 1 回引き、**行番号の並び順**から
    構造を読み取れば足ります（状態を覚える処理系が要らなくなる）
- インライン実行でファイルを読んだり加工したりしない
  - 使わない: `python3 -c` / `python -c` / `node -e` / `perl -e` / `ruby -e` / `bash -c` / `sh -c`
  - スクリプトファイルに退避して `python3 <path>` / `bash <path>` の形で実行するのも、
    hook がコマンド文字列しか見られない以上ガードレールを迂回する経路になります。
    その場しのぎのスクリプトを書いて実行することで確認作業を通そうとしてはいけません
  - 定型処理のためにスクリプトが必要な場合は、目的と処理内容を user に伝えて判断を仰ぐ
- `git` / `gh` / `pnpm` / `docker` / `sbx` はサンドボックス外で実行される（`excludedCommands`）
  ため、`cd A && cmd` ではなく `git -C <path>` / `pnpm --dir` / `make -C` / `npm --prefix`
  などのディレクトリ指定オプションを使うか、パス引数を絶対パスにする
